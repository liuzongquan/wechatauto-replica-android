# 安全边界与私有数据

## 允许的部署模型

操作人只应连接自己拥有或明确获准测试的 Android 设备和测试账号。设备解锁、USB 调试授权、无线配对、微信登录及任何系统授权提示，由操作人在设备上确认。本项目不绕过锁屏、不替用户同意授权、不自动 root/解锁引导程序/刷机、不修改 APK。默认 UI/Root 快照路径不注入微信；实验性 Frida 观察会在进程内挂钩方法，必须单独取得 attach 许可，不能从 root 读取许可推定。用户允许 root 读取方案；这仅适用于已获授权设备的最小范围只读数据访问，不是对其他设备、账号或任意系统文件的授权。

Python 主机 → 本机 ADB server → 获准设备 → Android UI 自动化。远程主机只经受控私网/VPN/SSH 隧道访问；不得把 ADB server 的 5037 端口、设备调试端口（常见 5555）或自动化服务暴露到公网。不要使用 `adb -a` 将 server 无限制监听到所有网卡。停用后断开调试连接，并按需要在设备上撤销调试授权。

ADB 授权意味着对设备的强控制能力。容器并不隔离被其控制的手机；授予容器 ADB 访问后，该容器可影响手机。不要把 Docker socket、整个主机目录、ADB 私钥目录或 USB 总线默认挂载给容器，不需要 `--privileged`。Frida 常见 27042 端口也不得暴露公网，ADB 环境变量不会自动建立安全可用的 Frida USB 传输。

## 数据来源必须分开

- `user_export`：操作人提供的标准化 JSON 档案、SQLite 导出、媒体文件；不是从 Android 微信自动提取的数据。
- UI 层级或截图：屏幕上的即时观测；不是完整历史，不具备数据库主键或全局增量序号保证。
- 确定性测试 fixture：合成输入；不能证明某个 Android/微信版本可用。

不应把昵称当作稳定账号 ID；同名收件人、多个匹配元素、未知版本、错误前台应用应阻止操作，而不是任选一个。选择器 profile 必须绑定实际包名与版本，不能随意扩大版本匹配范围来跳过检查。

## 副作用与失败

发送消息、转发、拨号、点赞、评论、拍一拍、创建标签、改备注、加好友和群管理都可能产生真实影响。先预演，核对目标、内容和操作；执行需要明确授权，群发尤其不能仅凭同名标签自动扩散。

已实现的写入默认严格要求提交前的当前账号证明。选择 `--assume-exclusive-device`/`SafetyPolicy.assume_exclusive_device=True` 是用户主动接受较弱的独占设备假设，不是修复账号证明缺失；若有其他控制器、人工触摸或账号切换可能，不应使用。报告中的 `assurance` 必须保留，不能将较弱先验包装成完整身份/原子性保证。

只读指令也可能产生本地证据、导航到账号页面或启动 UI 自动化服务；应在授权设备上运行。只读不等于不读取私人数据或完全不改变界面。副作用结果无法确定时应保留 `unknown`/错误状态，先人工核实设备与消息记录，不能盲目重试。执行日志不是微信送达回执。上游 UI SDK 的底层传输/服务恢复可能重试 RPC；本适配器固定已审查的 SDK 版本并通过单次底层 RPC 避免该自动重试。但观察与点击之间仍可能发生 UI 竞争，应用层去重日志和此缓解措施都不能证明端到端严格“最多一次”或远端送达，详见 [独立审查](QA_REVIEW.md)。

`failed_before_commit` 也不意味着界面已恢复原样：导航、输入草稿、标签选择或共享目录中的附件可能已存在。代码不会盲目返回、清空草稿或重试；由操作者检查并在授权范围内收尾。预演模式与“执行但提交前失败”必须分开理解。

## Root 与数据库副本

Root 是独立且高权限的通道，不是 UI profile 不匹配后的自动兜底。只访问显式指定账号、路径和数据库；Root 快照不自动枚举/导出全部账号，不修改 SELinux、挂载选项、进程内存或数据库原件。实验运行时密钥观察是另一路径：只能在已有可信 runtime 上、明确版本/账号/路径范围和单独 attach 授权下进行，可能影响时序或导致应用不稳定。不能为获取一致快照而未经批准强制停止微信、冻结进程或清理 WAL。

加密数据库、WAL/SHM、解密副本、密钥文件和媒体索引应视同聊天正文保护。密钥不要作为命令行明文、仓库配置或 CI secret 演示值；不要写到 shell 历史/日志。只使用操作者提供的授权密钥通道和经校验的数据库/SQLCipher profile。数据库与 WAL 来自不同时间或无法证明一致时，不得宣称全量一致历史；应拒绝或明确失败，不静默丢 WAL。Root 可读不等于已知道所有微信 8.x 的加密参数和表结构。

默认 keycapture attach 不启动/重启应用；可选 spawn 涉及 package force-stop/relaunch 和 zygote/system_server instrumentation，必须另有两个独立许可，仅支持 Android user 0。空闲预检不等于无强停副作用。见 [密钥模式边界](DATABASE_KEYS.md)。

## 日志、截图和导出

截图、UI XML、聊天导出、联系人、设备序列号和操作审计都可能包含个人信息：

1. 只保存到操作者控制的本地私有目录，限制访问和保留期。
2. 不自动上传到 GitHub Issues、Actions artifacts、公共仓库或第三方日志平台。
3. 报错时先分享已脱敏的异常类型、工具版本、Android 版本、微信版本和 profile 名称。
4. 真需提供截图/XML 时，逐项检查正文、昵称、头像、群名、二维码、路径、账号及设备标识；保留最小重现片段。
5. `.gitignore`/`.dockerignore` 是误操作防线，不是脱敏器；推送前仍要检查实际暂存文件。

CI 只使用合成 fixtures，不连接真实账号，不上传设备证据，不需要任何微信密码、ADB 密钥或访问令牌。禁止为排错把密钥写进仓库或截图。

## 报告问题

请通过目标仓库的私密安全报告渠道（如果仓库所有者已开启）披露敏感问题；否则先私下联系仓库所有者，勿把账号数据、利用细节或凭据贴到公开 Issue。普通 bug 可以公开报告脱敏环境信息、复现步骤和异常类型。
